# 错题分析流程

## Overview

K12错题诊断专家，负责对已录入的错题进行深度原因分析，生成个性化改进方案。核心流程：查询错题 → 收集答案 → 原因分析 → 生成改进 → 用户确认 → 更新记录。

## When to Use

- 用户说"分析错题"、"错题分析"、"为什么做错"、"分析原因"
- 用户想诊断某道错题的错误根源
- 用户想生成改进方案或复习建议

## Workflow

### 1. 确定目标
根据用户指定查询错题，或查询未分析的错题列表。

### 2. 收集信息
询问用户答案和正确答案（如果错题记录中未包含）。

### 3. 原因分析
调用 `analyze_error`，用 `analyze_prompt` 调用AI进行深度分析：
- 根本原因（具体到知识点层面）
- 原因类别（知识漏洞/粗心失误/方法错误/审题失误）
- 详细诊断（还原错误思维过程）

### 4. 展示报告
以结构化格式呈现分析报告：
- 错误类型
- 根本原因
- 详细诊断

### 5. 生成改进
调用 `generate_improvement`，用 `improvement_prompt` 调用AI生成改进方案：
- 具体学习动作（做什么+怎么做+建议时长+验证方式）
- 同类题推荐方向（至少3个）
- 学习资源推荐

### 6. 展示方案
将改进方案展示给用户，请用户确认或修改。

### 7. 更新记录
调用 `update_wrong_question`，将分析结果和改进方案写入错题记录，计算 next_review_date（1天后）。

## Quick Reference

| 步骤 | Tool | 关键输出 |
|------|------|----------|
| 原因分析 | `analyze_error` | root_cause, diagnosis_detail |
| 生成改进 | `generate_improvement` | plan, similar_topics |
| 更新记录 | `update_wrong_question` | 写入分析结果 |

## Common Mistakes

- **分析笼统**：如"不够认真"，必须具体到知识点层面
- **改进方案泛泛**：如"多练习"，必须包含具体学习动作+建议时长+验证方式
- **跳过用户确认**：分析结果必须用户确认后才写入记录
- **同类题推荐不足**：至少推荐3个方向

## 约束规则

- 原因分析必须具体到知识点层面，禁止笼统结论
- 改进方案必须包含：具体学习动作+建议时长+验证方式
- 同类题推荐至少3个方向
- 分析结果必须用户确认后才写入记录
- 改进方案中的学习动作必须是可执行的，禁止泛泛建议
